# 将当前数据迁移到 CloudStudio

使用 `manshi-cloud-current-data-日期时间.zip` 私密迁移包，包含导出时的源码和数据库，不使用只含源码的 initial-data 压缩包。

保留员工、姓名账号、密码、四角色权限、离职停用、主管分配、打卡、考勤规则、请假、薪资和操作日志。只清空云端副本的登录会话，迁移后重新登录，不修改本机数据库。该包含员工及薪资数据，请保存在自己的工作空间，不要提交到公开Git仓库。

## 新工作空间

1. 上传并解压迁移包，打开 `manshi-employee-system` 根目录。确认存在 `backend/data/manshi.sqlite3` 和 `migration/manifest.json`。
2. 环境需要Python 3.11+、Node.js 22.12+、npm。执行 `sh start.sh`，或点击平台运行按钮。
3. 脚本自动安装依赖、生成配置、核对迁移清单、备份数据库并保留数据升级，启动后端8000和前端3000。
4. 从端口面板打开3000实际预览地址，使用当前用户名和密码登录。若平台缺少预览地址环境变量，用 `sh start.sh --preview-url '平台实际HTTPS地址'` 启动。
5. 核对员工数量、新增员工、打卡时间、考勤规则、请假和薪资。查看历史打卡需选择对应月份。不要运行reset_initial_data.py重建工具。

一键脚本第一次导入自动核对数据库；成功后记录导入标记，后续新增的云端数据可以正常保留。手动 `python3 scripts/verify_cloud_data.py` 适用于首次登录或变更数据之前；发生正常业务变更后，与导出快照不一致属于预期。

## 已有数据的工作空间

先停止云端系统，单独备份云端已有数据库，再选择迁移目标。不要向正在运行或已有业务数据的目录直接覆盖解压。本迁移包复制本机导出时的快照，不自动合并两边数据。

## 重新导出

若打包后本机又新增了数据，在本机项目根目录执行 `backend/.venv/Scripts/python.exe -X utf8 scripts/package_current_data.py`，生成新包后再上传。每次使用新文件名，不覆盖旧包。迁移后统一使用云端操作，本机与云端不会自动同步。

详细启动参数见 [CloudStudio一键启动](CLOUDSTUDIO-ONE-CLICK.md)。
